# Contributing to H.U.M.A.N.

Thank you for considering a contribution to **HUMAN — Humanity’s Universal Mind And Network**.  
This project exists to develop a rational, long-term vision for a post-biological cognitive system.  
We welcome anyone willing to engage seriously with that vision.
Visualizations are welcome.

## Types of Contribution

We accept contributions in several forms:

- **Conceptual & Philosophical** – refinements to the core ideas, ethical frameworks, or the underlying motivation.  
  Relevant files: `IDEA.md`, `philosophy/00_origin_motivation.md`, `philosophy/WHITEPAPER.md`.
- **Formal / Mathematical** – improvements or extensions to the formal model, target function, or architectural definitions.  
  Relevant files: `core/FORMAL_MODEL.md`, `core/ARCHITECTURE.md`.
- **Research** – proposals, literature reviews, or critiques that help position HUMAN within existing AI research.  
  Relevant files: `research/RESEARCH_PROPOSAL.md`, `research/RESEARCH_PITCH.md`.
- **Simulation & Engineering** – concrete scenarios, simulation environments, or code that demonstrate aspects of the system.  
  Relevant files: `core/SIMULATION_ENVIRONMENT.md`, `research/SCIENTIFIC_FRAMING.md`.
- **Documentation & Translation** – clarifying existing texts, fixing inconsistencies, or translating the project into other languages.

If you are unsure where your contribution fits, open an issue and we will discuss it together.

## How to Contribute

1. **Open an Issue first.**  
   Describe what you would like to add, change, or discuss. This lets us align expectations before you spend time on a full contribution.

2. **Fork the repository and create a feature branch.**  
   Use a short, descriptive branch name (e.g., `formal-model-clarification`, `philosophy-motivation-edit`).

3. **Make your changes.**  
   - Keep the tone consistent with the surrounding documents (analytical, precise, avoiding unnecessary emotion).  
   - Use clear, straightforward English.  
   - If you introduce a new concept, explain it or link to an existing definition in the repository.  
   - Do not alter the fundamental vision of the project without prior discussion – significant shifts in direction must be agreed upon via an issue or discussion.

4. **Open a Pull Request.**  
   Reference the issue you opened. Provide a concise summary of what you did and why. If your change is visual (diagrams, structure), include a brief explanation in the PR description.

## Style & Tone Guidelines

- **Rational, not romantic.** We prefer precise reasoning over emotional language. The idea itself is ambitious enough; let the logic carry it.
- **Document structure matters.** If you add a new file, place it in the appropriate directory. Update any indexes or navigation references if they exist.
- **Link generously.** If your contribution touches a concept defined elsewhere (e.g., *substitutive immortality*, *Expansion Directive*, *Martian simulation*), provide a relative link to the relevant document.
- **Cite external sources.** If you reference a paper, blog post, or other work, include at least a minimal citation (author, year, title, URL).

## Conduct

We have a simple standard: engage with the ideas, not with personal attacks.  
Disagreement is expected, especially on philosophical and technical grounds, but it must remain constructive.  
Harassment, dismissive behaviour, or off-topic disruption will result in removal from the conversation.

## Where to Start

If you want to contribute but are unsure where to begin:

- Read `IDEA.md` first to understand the core vision.
- Then look through the open issues – some may be tagged `good first issue` or `help wanted`.
- For philosophical or motivational contributions, see the discussion threads linked in `philosophy/`.
- For technical improvements, review the formal model and the simulation restrictions.

## Questions?

Open an issue with the label `question`. We do not have a mailing list or chat server yet – for now, GitHub issues are the primary place for project discussion.
